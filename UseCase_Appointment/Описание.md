Use case: Проведение приема пациента врачом
Основной сценарий:
1.  Врач открывает расписание приемов в интерфейсе больницы
  - UI вызывает HospitalController.showSchedule()
  - HospitalController обращается к Schedule через зависимость
2.  Приложение отображает список запланированных приемов на текущий день
  - Schedule выполняет SQL-запрос через IDatabase для получения приемов врача
  - Данные возвращаются через executeQuery() с фильтрацией по дате и статусу
3.  Врач выбирает текущий прием пациента из списка
  -  UI передает ID выбранного приема в HospitalController
4.  Приложение открывает интерфейс приема с данными пациента и историей болезней
  -  HospitalController вызывает:
    1. MedicalRecords.getPatientVisits(patientId) для истории болезней
    2. MedicalRecords.getPatientData(patientId) для основной информации
  -  PostgreSQLDatabase выполняет JOIN-запросы для получения связанных данных
5.  Врач вносит текущие показатели пациента в интерфейсе приема
  -  Данные временно сохраняются в объекте Visit через Visit.addSymptoms(), Visit.addVitalSigns()
6.  Приложение автоматически сохраняет введенные данные в медицинскую карту пациента
  -  HospitalController вызывает MedicalRecords.updateData() с промежуточными данными
  -  Начинается транзакция через IDatabase.beginTransaction()
7.  Врач нажимает кнопку "Добавить диагноз"
  -  UI вызывает HospitalController.addDiagnosis()
8.  Приложение открывает окно с поиском по базе диагнозов (МКБ-10)
  -  HospitalController выполняет поиск в таблице МКБ через IDatabase
9.  Врач выбирает соответствующий диагноз из списка или вводит новый
  -  Выбранный диагноз передается в Visit.addDiagnosis()
10.  Врач добавляет комментарии и рекомендации по лечению
  -  Данные сохраняются в объекте Visit через Visit.addPrescription()
11.  Приложение сохраняет диагноз в медицинской записи приема
  -  HospitalController обновляет запись в таблице visits через MedicalRecords
12.  После завершения осмотра врач нажимает кнопку "Завершить прием"
  -  UI вызывает HospitalController.completeAppointment()
13.  Приложение проверяет заполнение обязательных полей (диагноз, рекомендации)
  -  HospitalController валидирует данные объекта Visit
  -  Проверяет наличие диагноза и как минимум одной рекомендации
14.  При отсутствии ошибок приложение помечает прием как завершенный
  -  Вызывается Visit.completeVisit(), который устанавливает статус "completed"
15.  Приложение сохраняет все изменения в базе данных
   - HospitalController выполняет:
    1)  MedicalRecords.addVisit(visit) для сохранения данных приема
    2)  Schedule.updateAppointmentStatus() для обновления расписания
    3)  IDatabase.commit() для фиксации транзакции
  -  Вызывается HospitalController.notifyObservers() для уведомления пациента
Альтернативные сценарии:
Отмена приема:
1.  Врач нажимает "Отменить прием" при неявке пациента
2.  Приложение предлагает выбрать причину отмены
3.  Врач выбирает причину "Пациент не явился"
4.  Врач подтверждает отмену приема
5.  HospitalController вызывает Schedule.cancelAppointment()
6.  Приложение помечает прием как отмененный в базе данных
7.  Приложение освобождает время в расписании врача через Schedule.updateDoctorSchedule()
Ошибка валидации данных:
1.  При попытке завершить прием с незаполненными обязательными полями
2.  HospitalController возвращает ошибку с перечнем незаполненных полей
3.  UI отображает сообщение об ошибке врачу
4.  Врач заполняет недостающие данные и повторяет попытку завершения
Постусловия:
- Медицинская карта пациента содержит обновленные данные о приеме через MedicalRecords
- Прием имеет статус "Завершен" в расписании через Schedule
-  Диагноз и рекомендации доступны для просмотра в личном кабинете пациента
-  Пациент получает уведомление через механизм IObserver (Patient.update())
-  Врач может начать следующий запланированный прием
-  Все изменения зафиксированы в PostgreSQLDatabase через транзакцию
-  Создана полная запись Visit в базе данных со всеми связанными данными
