Use Case: Регистрация пациента и создание медицинской карты

Основной сценарий:

1. Пациент запускает мобильное приложение больницы.
2. UI отображает начальный экран с кнопками "Войти" и "Зарегистрироваться".
3. Пациент нажимает кнопку "Зарегистрироваться".
4. UI отображает экран выбора способа регистрации с опциями:
   - Зарегистрироваться с помощью аккаунта "Госуслуги"
   - Зарегистрироваться с помощью аккаунта "MAX"
   - Зарегистрироваться с помощью аккаунта "ВК-ID"
   - Зарегистрироваться без аккаунта
5. Пациент выбирает один из предложенных способов (например, "Госуслуги").
6. UI передает запрос в HospitalController для обработки регистрации.
7. HospitalController использует интерфейс IExternalAuthentication и вызывает метод authorizeViaGosuslugi().
8. Приложение перенаправляет Пациента в соответствующую Систему внешней аутентификации (Gosuslugi).
9. Пациент проходит процесс аутентификации в стороннем сервисе.
10. IExternalAuthentication получает токен авторизации и данные пользователя, вызывая getUserData() у сервиса Gosuslugi.
11. HospitalController вызывает свой метод registerPatient(), передавая полученные данные.
12. HospitalController создает новый объект Patient с полученными данными (ФИО, дата рождения, паспорт, полис).
13. HospitalController вызывает метод createMedicalRecord().
14. HospitalController обращается к классу MedicalRecords, который создает новую запись через createRecord() и связывает ее с пациентом через linkToPatient().
15. MedicalRecords использует IDatabase (через PostgreSQLDatabase или SQLiteDatabase) для сохранения данных пациента и медицинской карты, вызывая executeQuery() в рамках транзакции (beginTransaction()).
16. HospitalController подтверждает транзакцию в IDatabase через commit().
17. HospitalController, реализующий IObservable, уведомляет всех подписчиков (в данном случае нового Patient) о успешной регистрации через notifyObservers().
18. Patient, реализующий IObserver, получает уведомление и может обновить свое состояние.
19. UI перенаправляет Пациента в личный кабинет (раздел "Профиль").
20. Приложение отображает уведомление об успешной регистрации и запрос на заполнение медицинских данных.
21. Пациент вводит медицинские данные (рост, вес, хронические заболевания, аллергии).
22. HospitalController вызывает updateMedicalData() для обновления медицинской карты.
23. MedicalRecords обновляет данные через updateData(), сохраняя изменения в IDatabase.
24. Use case завершается.

Альтернативные сценарии:

Альтернатива A1: У пациента уже есть аккаунт
1. На шаге 3 Пациент нажимает "Войти".
2. UI отображает экран входа.
3. HospitalController вызывает authenticateUser() для проверки учетных данных через IExternalAuthentication или напрямую через IDatabase.
4. При успешной аутентификации UI перенаправляет в личный кабинет.

Альтернатива A2: Регистрация без использования стороннего аккаунта
1. На шаге 5 Пациент выбирает "Зарегистрироваться без аккаунта".
2. UI отображает форму ручного ввода данных.
3. Пациент вводит данные (ФИО, дата рождения, паспорт, полис).
4. HospitalController выполняет валидацию данных (например, проверяя их наличие и формат).
5. При успешной валидации продолжается с шага 12 основного сценария.

Альтернатива A3: Ошибка аутентификации через сторонний сервис
1. На шаге 10 IExternalAuthentication возвращает ошибку авторизации.
2. HospitalController откатывает транзакцию через rollback() в IDatabase.
3. UI отображает сообщение об ошибке.
4. Use case возвращается к шагу 4.

Альтернатива A4: Пользователь пропускает шаг ввода медицинских данных
1. На шаге 21 Пациент нажимает "Пропустить".
2. MedicalRecord сохраняется с только базовыми данными.
3. Дополнительные медицинские данные могут быть добавлены позже через вызов updateMedicalData() в HospitalController.

Поток данных и особенности реализации (согласно диаграмме):

1. Аутентификация: HospitalController -> IExternalAuthentication -> (Gosuslugi/Max/VKId) -> IDatabase.
2. Создание пациента: HospitalController -> Patient. Пациент регистрируется как IObserver.
3. Управление медицинскими записями: HospitalController -> MedicalRecords. MedicalRecords является агрегатом, управляющим коллекциями Patient и Visit, и использует IMedicalRecordRepository (реализованный MedicalRecordRepository) для персистентности.
4. Сохранение данных: Все операции с данными в конечном счете выполняются через единый интерфейс IDatabase его реализациями (PostgreSQLDatabase/SQLiteDatabase).
5. Управление транзакциями: HospitalController управляет транзакциями через вызовы beginTransaction() -> commit()/rollback() у IDatabase.
6. Уведомления: HospitalController (как IObservable) уведомляет Patient и Doctor (как IObserver) о значимых событиях.

Постусловия:

- Создана новая учетная запись Patient в системе.
- Создана MedicalRecord, связанная с учетной записью пациента.
- Данные сохранены в выбранной БД (PostgreSQL/SQLite) через единый интерфейс IDatabase.
- Пациент зарегистрирован как IObserver и аутентифицирован в системе.
- Медицинская карта содержит базовые или полные данные в зависимости от выполнения сценария.
