Use Case: Регистрация пациента и создание медицинской карты

Основной сценарий:
1. Пациент запускает мобильное приложение больницы.
2. UI отображает начальный экран с кнопками "Войти" и "Зарегистрироваться".
3. Пациент нажимает кнопку "Зарегистрироваться".
4. UI отображает экран выбора способа регистрации с опциями:
   - Зарегистрироваться с помощью аккаунта "Госуслуги"
   - Зарегистрироваться с помощью аккаунта "MAX"
   - Зарегистрироваться с помощью аккаунта "ВК-ID"
   - Зарегистрироваться без аккаунта
5. Пациент выбирает один из предложенных способов (например, "Госуслуги").
6. UI передает запрос в HospitalController для обработки регистрации.
7. HospitalController создает экземпляр ExternalAuthentication и вызывает authorizeViaGosuslugi().
8. Приложение перенаправляет Пациента в соответствующую Систему внешней аутентификации.
9. Пациент проходит процесс аутентификации в стороннем сервисе.
10. ExternalAuthentication получает токен авторизации и данные пользователя через getUserData().
11. HospitalController вызывает registerPatient(), передавая полученные данные.
12. HospitalController создает новый объект Patient с полученными данными (ФИО, дата рождения, паспорт, полис).
13. HospitalController вызывает createMedicalRecord() для создания медицинской карты.
14. MedicalRecords создает новую запись через createRecord() и связывает с пациентом через linkToPatient().
15. База данных (PostgreSQL/SQLite) сохраняет данные пациента и медицинской карты через executeQuery().
16. HospitalController подтверждает транзакцию в IDatabase.
17. UI перенаправляет Пациента в личный кабинет (раздел "Профиль").
18. Приложение отображает уведомление об успешной регистрации и запрос на заполнение медицинских данных.
19. Пациент вводит медицинские данные (рост, вес, хронические заболевания, аллергии).
20. HospitalController вызывает updateMedicalData() для обновления медицинской карты.
21. MedicalRecords обновляет данные через updateData(), сохраняя изменения в базе данных.
22. Use case завершается.

 Альтернативные сценарии:

Альтернатива A1: У пациента уже есть аккаунт
1. На шаге 3 Пациент нажимает "Войти".
2. UI отображает экран входа.
3. HospitalController вызывает authenticateUser() для проверки учетных данных.
4. При успешной аутентификации UI перенаправляет в личный кабинет.

Альтернатива A2: Регистрация без использования стороннего аккаунта
1. На шаге 5 Пациент выбирает "Зарегистрироваться без аккаунта".
2. UI отображает форму ручного ввода данных.
3. Пациент вводит данные (ФИО, дата рождения, паспорт, полис).
4. HospitalController вызывает validateData() для проверки корректности данных.
5. При успешной валидации продолжается с шага 12 основного сценария.

Альтернатива A3: Ошибка аутентификации через сторонний сервис
1. На шаге 10 ExternalAuthentication возвращает ошибку авторизации.
2. HospitalController откатывает транзакцию через rollback().
3. UI отображает сообщение об ошибке.
4. Use case возвращается к шагу 4.

Альтернатива A4: Пользователь пропускает шаг ввода медицинских данных
1. На шаге 19 Пациент нажимает "Пропустить".
2. MedicalRecord сохраняется с только базовыми данными.
3. Дополнительные медицинские данные могут быть добавлены позже через updateMedicalData().


Поток данных в бекенде:
1. **Аутентификация**: ExternalAuthentication → IDatabase
2. **Создание пациента**: HospitalController → Patient → MedicalRecords
3. **Сохранение данных**: MedicalRecords → IDatabase (executeQuery + commit)
4. **Управление транзакциями**: beginTransaction() → commit()/rollback()

 Особенности реализации:
- MedicalRecords выступает как агрегат, содержащий коллекции Patient и Visit
- Все операции с базой данных проходят через единый интерфейс IDatabase
- HospitalController инкапсулирует всю бизнес-логику регистрации
- Поддерживается транзакционность для обеспечения целостности данных

 Постусловия:
- Создана новая учетная запись Patient в системе
- Создана MedicalRecord, связанная с учетной записью пациента
- Данные сохранены в выбранной БД (PostgreSQL/SQLite) 
- Пациент аутентифицирован и имеет доступ к личному кабинету
- Медицинская карта содержит базовые или полные данные в зависимости от сценария
