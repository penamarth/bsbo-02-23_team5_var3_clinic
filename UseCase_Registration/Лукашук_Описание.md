Use Case: Регистрация пациента и создание медицинской карты

Основной сценарий:

1. Пациент открывает приложение больницы на телефоне
2. Приложение показывает начальный экран с кнопками "Войти" и "Зарегистрироваться"
3. Пациент нажимает "Зарегистрироваться"
4. Приложение предлагает выбрать способ регистрации:
   - Через Госуслуги
   - Через MAX
   - Через ВКонтакте
   - Обычная регистрация (ввод данных вручную)
5. Пациент выбирает, например, "Госуслуги"
6. Приложение обрабатывает запрос на регистрацию
7. Система начинает регистрацию через выбранный сервис
8. Приложение переходит в сервис Госуслуг для подтверждения личности
9. Пациент проходит проверку в Госуслугах
10. Система получает данные пациента из Госуслуг
11. Система начинает процесс создания учетной записи пациента
12. Создается профиль пациента с полученными данными (ФИО, дата рождения, паспорт, полис)
13. Система начинает создание медицинской карты
14. Создается медицинская карта и привязывается к профилю пациента
15. Система сохраняет данные пациента и медицинской карты в базу данных
16. Система подтверждает сохранение всех данных
17. Система отправляет уведомление о успешной регистрации
18. Пациент получает уведомление о завершении регистрации
19. Приложение переводит пациента в личный кабинет (раздел "Профиль")
20. Приложение показывает сообщение об успешной регистрации и предлагает заполнить медицинские данные
21. Пациент вводит медицинские данные (рост, вес, хронические заболевания, аллергии)
22. Система обновляет медицинскую карту новыми данными
23. Медицинская карта сохраняет обновленные данные
24. Процесс регистрации завершен

Альтернативные сценарии:

Альтернатива A1: У пациента уже есть аккаунт
1. На шаге 3 Пациент нажимает "Войти"
2. Приложение показывает экран входа
3. Система проверяет данные для входа
4. При успешной проверке приложение открывает личный кабинет

Альтернатива A2: Обычная регистрация (без использования сторонних сервисов)
1. На шаге 5 Пациент выбирает "Обычная регистрация"
2. Приложение показывает форму для ввода данных
3. Пациент вводит данные (ФИО, дата рождения, паспорт, полис)
4. Система проверяет корректность введенных данных
5. При успешной проверке продолжается с шага 12 основного сценария

Альтернатива A3: Ошибка при регистрации через сторонний сервис
1. На шаге 10 система не может получить данные из сервиса
2. Система отменяет начатую регистрацию
3. Приложение показывает сообщение об ошибке
4. Процесс возвращается к шагу 4 выбора способа регистрации

Альтернатива A4: Пациент пропускает ввод медицинских данных
1. На шаге 21 Пациент нажимает "Пропустить"
2. Медицинская карта сохраняется только с основными данными
3. Дополнительные медицинские данные можно будет добавить позже в личном кабинете

Поток данных и особенности реализации (согласно диаграмме):

1. Аутентификация: HospitalController -> IExternalAuthentication -> (Gosuslugi/Max/VKId) -> IDatabase.
2. Создание пациента: HospitalController -> Patient. Пациент регистрируется как IObserver.
3. Управление медицинскими записями: HospitalController -> MedicalRecords. MedicalRecords является агрегатом, управляющим коллекциями Patient и Visit, и использует IMedicalRecordRepository (реализованный MedicalRecordRepository) для персистентности.
4. Сохранение данных: Все операции с данными в конечном счете выполняются через единый интерфейс IDatabase его реализациями (PostgreSQLDatabase/SQLiteDatabase).
5. Управление транзакциями: HospitalController управляет транзакциями через вызовы beginTransaction() -> commit()/rollback() у IDatabase.
6. Уведомления: HospitalController (как IObservable) уведомляет Patient и Doctor (как IObserver) о значимых событиях.

Постусловия:

- Создана новая учетная запись Patient в системе.
- Создана MedicalRecord, связанная с учетной записью пациента.
- Данные сохранены в выбранной БД (PostgreSQL/SQLite) через единый интерфейс IDatabase.
- Пациент зарегистрирован как IObserver и аутентифицирован в системе.
- Медицинская карта содержит базовые или полные данные в зависимости от выполнения сценария.
