Use Case: Запись на прием к врачу

Основной сценарий:
1. Пациент запускает мобильное приложение поликлиники и входит в систему (предполагается, что пациент уже зарегистрирован и аутентифицирован).
2. UI отображает личный кабинет с опциями, включая "Записаться на прием". 
3. Пациент нажимает кнопку "Записаться на прием". 
4. UI отображает экран выбора врача или специализации. 
5. Пациент выбирает специализацию (например, "Терапевт") или конкретного врача. 
6. UI передает запрос в HospitalController для получения доступных слотов. 
7. HospitalController вызывает метод Schedule.getFreeSlots() для выбранного врача или специализации. 
8. Schedule проверяет доступность через checkAvailability() и запрашивает данные из базы данных с помощью IDatabase.executeQuery(). 
9. Schedule возвращает список свободных слотов (дата, время) в HospitalController. 
10. HospitalController передает данные в UI для отображения. 
11. UI показывает календарь или список свободных слотов. 
12. Пациент выбирает подходящий слот. 
13. UI передает выбор в HospitalController для подтверждения записи. 
14. HospitalController вызывает Schedule.confirmAppointment() для резервирования слота. 
15. Schedule создает новый объект Visit с данными пациента, врача, даты и времени. 
16. Schedule добавляет запись в базу данных через IDatabase.executeQuery() и подтверждает транзакцию commit(). 
17. HospitalController уведомляет observers (включая Patient) через notifyObservers() о успешной записи. 
18. UI отображает подтверждение записи и детали (врач, дата, время). 
19. Use case завершается.

 Альтернативные сценарии:

Альтернатива A1: Нет свободных слотов
1. На шаге 9 Schedule возвращает пустой список слотов. 
2. HospitalController уведомляет UI об отсутствии слотов. 
3. UI отображает сообщение "Нет свободных слотов" и предлагает выбрать другого врача или дату. 
4. Use case возвращается к шагу 5.

Альтернатива A2: Отмена записи пациентом
1. После шага 18 Пациент решает отменить запись (через отдельный раздел в личном кабинете). 
2. UI передает запрос в HospitalController. 
3. HospitalController вызывает Schedule.cancelAppointment(). 
4. Schedule удаляет Visit из базы данных через IDatabase.executeQuery() и rollback() при ошибке. 
5. HospitalController уведомляет observers об отмене.

Альтернатива A3: Ошибка в базе данных во время записи
1. На шаге 16 IDatabase возвращает ошибку при executeQuery(). 
2. HospitalController откатывает транзакцию через rollback(). 
3. UI отображает сообщение об ошибке. 
4. Use case возвращается к шагу 12 для повторной попытки. 
5. Альтернатива A4: Выбор врача по рекомендации 
6. На шаге 5 Пациент выбирает опцию "Рекомендованный врач" (на основе истории болезни). 
7. HospitalController запрашивает MedicalRecords.getHistory() для пациента. 
8. На основе данных (например, предыдущие диагнозы) Schedule.selectDoctor() предлагает подходящего врача. 
9. Продолжается с шага 7 основного сценария. 

Поток данных в бекенде:
1. **Получение слотов**: HospitalController → Schedule → IDatabase 
2. **Создание записи**: HospitalController → Schedule → Visit → IDatabase 
3. **Уведомления**: HospitalController (как IObservable) → IObserver (UI, Patient)
4. **Управление транзакциями**: beginTransaction() → commit()/rollback()

Особенности реализации:
- Schedule управляет всеми операциями с расписанием, включая проверку конфликтов и обновление слотов.
- HospitalController координирует процесс, инкапсулируя бизнес-логику записи.
- Visit создается как часть MedicalRecords для будущей связи с историей болезни.
- Поддерживается observer pattern для уведомлений о изменениях в расписании (например, для пациента и врача).
- Все взаимодействия с базой данных идут через IDatabase для абстракции (PostgreSQL или SQLite).

Постусловия:
- Создан новый объект Visit в системе, связанный с пациентом и врачом.
- Слот в расписании врача обновлен (занят).
- Пациент получает уведомление и доступ к деталям записи в личном кабинете.
- Данные сохранены в выбранной БД с обеспечением целостности через транзакции.
- Система готова к дальнейшим действиям, таким как проведение приема или отмена.
